# Strategy presentation structure — v0.4

## Default slide anatomy

Each slide should have:
- one headline that states the point;
- at most one short explanatory paragraph;
- one main evidence/visual pattern;
- optional source note;
- optional route/stop context when the deck is route-first.

## Route-first default

When the source describes a program, strategy journey or sequence:
- slide one can be the route itself;
- route stops become chapter anchors;
- later slides retain their stop number/context;
- portrait phone shows the journey vertically;
- phone landscape/desktop shows the full route;
- `Lead the room` is optional only when the Artifact runtime supports room capability.

Do not invent a route for non-sequential content.

## Visual rhythm

Mix:
- deep-teal/night high-impact slides;
- light editorial evidence slides;
- approved brand-gradient or template-ground covers/transitions;
- occasional playable network slides when connection/community is the point;
- data slides where the number is dominant;
- real-person/team insight cards only when supplied.

Do not make every slide the same card grid.

## Hub relationship

The deck is a story. The Hub is the reference.

If the audience needs all methodology, research, calendar, people and source detail, send them to the Hub instead of bloating the presentation.

If a coordinated Hub + deck uses an approved shared route model, reuse it. Otherwise presentation-specific narrative compression is allowed as long as it stays source-faithful.
